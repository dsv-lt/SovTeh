# 🧭 Полная инструкция по работе со Swagger UI (`http://localhost:8000/docs`)

Страница **`http://localhost:8000/docs`** — это встроенная интерактивная панель управления REST API проекта **SovTeh Hybrid RAG & AI Plot Assistant API** (`v2.0.0`) на базе **Swagger UI**. Через неё можно тестировать все локальные ML/DL-модели, RAG-поиск по базе сюжетов и многошаговых ИИ-агентов прямо из браузера — без написания кода и без сторонних программ вроде Postman.

---

## 1. Как открыть страницу и подготовить сервер

1. Убедитесь, что в корне проекта создан файл `.env` с вашим API-ключом (`LLM_API_KEY=...`) — он нужен для эндпоинтов `/ask` и `/agent`. Эндпоинты `/health` и `/classify` работают полностью офлайн даже без ключа.
2. Запустите FastAPI-сервер в терминале из корня репозитория:
   ```bash
   uvicorn src.app:app --host localhost --port 8000 --reload
   ```
   > **Совет для быстрого старта на слабом CPU:** если хотите запустить сервер за 1–2 секунды на быстром символьном классификаторе вместо `ruBERT-base + LoRA`, перед запуском задайте `CLASSIFIER_BACKEND=baseline` (в Windows PowerShell: `$env:CLASSIFIER_BACKEND="baseline"`).
3. Дождитесь в логах строки:
   ```text
   Application ready to serve requests (classifier=...)
   ```
   *(До появления этой строки сервер ещё загружает модели и строит индекс `FAISS` — обновлять `/docs` нужно после неё.)*
4. Откройте в браузере **`http://localhost:8000/docs`** (адрес `http://localhost:8000/` также автоматически перенаправляет на `/docs`).
   * Дополнительно доступны:
     * **`http://localhost:8000/redoc`** — альтернативная документация в стиле «справочника» (удобна только для чтения, без кнопок отправки запросов);
     * **`http://localhost:8000/openapi.json`** — сырая JSON-спецификация всех схем и маршрутов OpenAPI.

## 2. Из чего состоит страница `/docs` (разбор каждого элемента интерфейса)

### 2.1. Верхняя шапка (Header)
* **`SovTeh Hybrid RAG & AI Plot Assistant API`** и бейдж **`2.0.0`** **`OAS 3.1`** — название и версия API из `src/app.py`.
* Ссылка **`/openapi.json`** под заголовком — открывает или скачивает полную машиночитаемую схему API (её можно импортировать в Postman или Insomnia).
* Краткое описание возможностей сервиса под ссылкой.

### 2.2. Список эндпоинтов (карточки маршрутов)
В разделе `default` отображаются **4 доступных маршрута** (корневой `/` скрыт через `include_in_schema=False`, так как служит только редиректом):
1. Синяя полоса **`GET /health`** — проверка готовности сервиса.
2. Зелёная полоса **`POST /classify`** — локальная офлайн-классификация стиля (64 автора).
3. Зелёная полоса **`POST /ask`** — гибридный RAG-конвейер (ML-фильтр жанра + семантический поиск RuBERT/FAISS + ответ LLM по API).
4. Зелёная полоса **`POST /agent`** — многошаговый ИИ-агент с инструментами (`native`, `json`, `framework`) и режимами UI (`Аналитик`, `Критик`, `RAG`).

**Действия со строкой эндпоинта:**
* **Клик по любой части цветной полосы** (или по стрелке `⌄` / `⌃` справа) — разворачивает или сворачивает карточку эндпоинта.
* **Клик по тексту пути** (`/ask`, `/classify` и т.д.) — подставляет якорь в URL браузера (удобно, чтобы скопировать прямую ссылку на конкретный метод).

### 2.3. Кнопки и вкладки внутри раскрытой карточки эндпоинта
Когда вы раскрыли карточку `POST /...` или `GET /...`, внутри вы видите следующие элементы:

| Элемент интерфейса | Где находится | Что делает при нажатии / использовании |
|---|---|---|
| **`Parameters`** | Верхняя секция карточки | Показывает URL/Query/Header-параметры. Во всех 4 эндпоинтах `SovTeh` отображается `No parameters` — все данные передаются через тело JSON (`Request body`). |
| **`Try it out`** | Справа в шапке секции `Parameters` | **Главное действие для старта:** переводит карточку из режима чтения в интерактивный режим — разблокирует текстовое поле JSON и показывает кнопки **`Execute`** и **`Cancel`**. |
| **`Cancel`** | На месте `Try it out` после её нажатия | Выходит из интерактивного режима и возвращает карточку к виду «только чтение». |
| **`Reset`** | Рядом с `Cancel` (появляется после редактирования поля JSON) | Сбрасывает отредактированный вами JSON обратно к исходному шаблону по умолчанию. |
| **Вкладка `Example Value`** | Над полем JSON в `Request body` | Показывает готовый шаблон JSON, который можно редактировать и отправлять. |
| **Вкладка `Schema`** | Рядом с `Example Value` | Открывает подробное дерево полей: тип (`string`, `integer`, `number`), обязательность (красная звёздочка **`*`**), ограничения (`minLength`, `maxLength`, `minimum`, `maximum`, `pattern`, значения `default`) и описания из `src/schemas.py`. |
| **Поле `Media type`** | Справа в заголовке `Request body` | Выбор формата тела запроса (`application/json`). Оставляйте без изменений. |
| **Текстовое поле JSON** | Под вкладкой `Example Value` | Сюда вставляется ваш JSON-запрос. **Важно:** соблюдайте синтаксис JSON (двойные кавычки `"..."`, без лишней запятой после последнего поля). |
| **Синяя кнопка `Execute`** | Под полем JSON (на всю ширину блока) | Отправляет реальный HTTP-запрос на запущенный локальный сервер `http://localhost:8000/...` и ждёт ответ. Во время работы нейросети или LLM вместо результата крутится индикатор загрузки. |
| **Кнопка `Clear`** | Справа от кнопки `Execute` (появляется после первого ответа) | Очищает полученный ранее результат (`Curl`, `Request URL`, `Server response`), не сбрасывая введённый вами текст в JSON-поле. |

### 2.4. Блок результата после нажатия `Execute` (`Responses`)
Сразу под кнопкой `Execute` появляются три подблока:
1. **`Curl`** — готовая консольная команда `curl -X 'POST' ...`, точно повторяющая отправленный вами запрос. Иконка копирования в правом нижнем углу чёрного поля копирует команду в буфер обмена.
2. **`Request URL`** — точный адрес, на который ушёл запрос (например, `http://localhost:8000/ask`).
3. **`Server response`** — фактический ответ сервера:
   * **`Code`** — HTTP-статус ответа (`200` — успех; `400`/`422`/`502`/`503`/`504` — см. таблицу ошибок в Разделе 4).
   * **`Response body`** — JSON-ответ от FastAPI. Справа внизу внутри чёрного поля есть две кнопки:
     * **`Copy`** (значок двух листов) — копирует весь JSON ответа в буфер обмена;
     * **`Download`** — скачивает ответ на диск в виде файла `response_<timestamp>.json` (удобно, чтобы сохранить длинный разбор от `/ask` или пошаговую трассировку от `/agent`).
   * **`Response headers`** — служебные HTTP-заголовки ответа. Здесь можно убедиться, что сервер отдал `content-type: application/json; charset=utf-8` (гарантия корректной кириллицы в Windows PowerShell).
4. Ниже под названием **`Responses`** (или `Links` / коды `200`, `422`) остаётся справочная документация по ожидаемым структурам ответа с собственными вкладками **`Example Value`** и **`Schema`**.

### 2.5. Нижний раздел `Schemas`
В самом низу страницы `/docs` находится блок **`Schemas`**. Нажмите на название любой схемы, чтобы раскрыть контракт данных (все они описаны в `src/schemas.py`):
* `QueryRequest`, `QueryResponse` — вход и выход для `/ask` (и вход для `/classify`).
* `ClassifyResponse`, `AuthorScore` — выход `/classify` и элементы рейтинга `top_authors`.
* `AgentRequest`, `AgentResponse`, `AgentStepTrace` — вход, выход и формат каждого шага агента в `/agent`.
* `HealthResponse` — формат ответа `/health`.
* `HTTPValidationError`, `ValidationError` — стандартный формат деталей ошибки `422`.

## 3. Пошаговая инструкция по каждому из 4 эндпоинтов

Ниже приведены готовые сценарии **«нажал → вставил JSON → получил результат»** для всех четырёх маршрутов.

---

### 3.1. `GET /health` — проверка состояния сервера
**Когда использовать:** сразу после запуска `uvicorn`, чтобы убедиться, что сервер отвечает и локальный классификатор загружен в память. Ключ LLM не требуется.

**Порядок действий:**
1. Нажмите на синюю панель **`GET /health`**.
2. Нажмите **`Try it out`**.
3. Нажмите синюю кнопку **`Execute`**.

**Что проверять в `Server response`:**
* `Code`: должен быть **`200`**.
* `Response body`:
  ```json
  {
    "status": "ok",
    "model_loaded": true
  }
  ```
  * `status: "ok"` — FastAPI принимает запросы.
  * `model_loaded: true` — модель классификатора (`LoraClassifier` или `BaselineClassifier`) успешно загружена в `app.state.classifier`.

---

### 3.2. `POST /classify` — офлайн-определение стиля автора (64 классика)
**Когда использовать:** нужно быстро определить, на кого из 64 русских писателей-классиков похож стиль отрывка текста. Работает полностью локально, без интернета и без `LLM_API_KEY`.

**Порядок действий:**
1. Нажмите на зелёную панель **`POST /classify`**.
2. Нажмите **`Try it out`**.
3. Вставьте в поле `Request body` JSON-запрос, например:
   ```json
   {
     "question": "В саду за старой усадьбой тихо осыпались липы; уездный доктор сидел на террасе, пил остывший чай и молча смотрел на серый пруд.",
     "k": 3
   }
   ```
   *(Поле `temperature` можно оставить как в шаблоне `0.7` или не указывать — схема `QueryRequest` общая с `/ask`, но локальный классификатор `temperature` не использует.)*
4. Нажмите **`Execute`**.

**Поля запроса (`QueryRequest`):**
* **`question`** *(обязательно, `1..15000` символов)* — фрагмент текста на русском языке. Если передать пустую строку `""` или одни пробелы, сервер вернёт `400 {"detail": "Пустой вопрос"}`.
* **`k`** *(необязательно, целое `1..10`, по умолчанию `3`)* — сколько самых вероятных кандидатов вернуть в массиве `top_authors`.

**Что вернётся в `Response body` (`200 OK`):**
```json
{
  "predicted_author": "Чехов А",
  "confidence": 0.9842,
  "model_name": "ruBert-base + LoRA (64 authors)",
  "top_authors": [
    { "author": "Чехов А", "probability": 0.9842 },
    { "author": "Бунин И", "probability": 0.0091 },
    { "author": "Тургенев И", "probability": 0.0034 }
  ]
}
```
* `predicted_author` — главный победитель (автор с максимальной вероятностью).
* `confidence` — вероятность главного предсказания от `0.0` до `1.0`.
* `model_name` — какая именно локальная модель отработала (`LoraClassifier` или `BaselineClassifier`).
* `top_authors` — список из `k` ближайших авторов с вероятностями.

---

### 3.3. `POST /ask` — гибридный RAG-поиск сюжетов и ответ LLM
**Когда использовать:** основной пользовательский сценарий. Система:
1. определит жанр вопроса локальным фильтром `HashingVectorizer + SGDClassifier` и авторский стиль;
2. найдёт топ-`k` самых подходящих сюжетов в `data/plots_dataset.csv` с помощью `FAISSVectorIndex` (`RuBERT` + гибридный скоринг);
3. передаст найденные карточки в настроенную облачную/локальную LLM и вернёт точный ответ строго по выписке (или честно предупредит, если точного сюжета в базе нет, и порекомендует топ-книги по рейтингу).

> **Требование:** в `.env` должен быть указан рабочий ключ (`LLM_API_KEY`, `GROQ_API_KEY`, `OPENROUTER_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY` или `GIGACHAT_CREDENTIALS`).

**Порядок действий:**
1. Нажмите на зелёную панель **`POST /ask`**.
2. Нажмите **`Try it out`**.
3. Вставьте JSON:
   ```json
   {
     "question": "Найди сюжет про космическую экспедицию к Марсу и расскажи, что там происходит",
     "k": 3,
     "temperature": 0.3
   }
   ```
4. Нажмите **`Execute`**.

**Поля запроса (`QueryRequest`):**
* **`question`** *(обязательно, `1..15000` символов)* — вопрос по сюжету, теме или описанию произведения.
* **`k`** *(необязательно, `1..10`, по умолчанию `3`)* — сколько лучших карточек сюжетов из `data/plots_dataset.csv` передать в контекст LLM (они же вернутся в `sources`).
* **`temperature`** *(необязательно, `0.0..2.0`, по умолчанию `0.7`)* — «креативность» LLM. Для строгого пересказа фактов из базы ставьте `0.0–0.3`, для более живого слога — `0.7`.

**Что вернётся в `Response body` (`200 OK`):**
* `answer` — финальный текст ответа LLM на русском языке.
* `sources` — список из `k` текстовых карточек сюжетов (автор, название, жанр, рейтинг, описание), на основе которых отвечала модель. Удобно проверять, что LLM ничего не выдумала.
* `predicted_author` — ближайший авторский стиль по тексту вашего вопроса.
* `predicted_genre` — один из 7 макро-жанров, определённый фильтром `HashingVectorizer + SGDClassifier` + контекстом запроса.
* `confidence` — уверенность классификатора стиля (`0.0..1.0`).
* `model_name` — имя активной локальной модели.
* `generated_text` — дубликат `answer` для совместимости с клиентами.

---

### 3.4. `POST /agent` — многошаговый автономный ИИ-агент и режимы UI
Эндпоинт `/agent` поддерживает **два разных семейства сценариев** в зависимости от поля **`mode`**:

> ⚠️ **ОЧЕНЬ ВАЖНО для Swagger UI:**
> Когда вы нажимаете **`Try it out`** в `POST /agent`, Swagger UI по умолчанию подставляет в шаблон:
> ```json
> "mode": "string"
> ```
> В коде `src/app.py` проверка устроена так: если поле `mode` заполнено **любой непустой строкой** (включая `"string"`!), сервер игнорирует `approach` (`native`/`json`/`framework`) и запускает ветку UI-режима (`Аналитик` / `Критик` / `RAG`)!
>
> Поэтому:
> * если хотите тестировать **агента с инструментами (`native` / `json` / `framework`)** — обязательно замените `"mode": "string"` на **`"mode": null`** (или удалите строку с `"mode"`);
> * если хотите запустить **режим веб-интерфейса** — напишите в `"mode"` одно из слов: `"Аналитик"`, `"Критик"` или `"RAG"`.

#### Вариант А. Многошаговый агент с инструментами (`classify_style`, `search_plots`, `author_metrics`, `calc`)
Используйте `mode: null` и выберите одну из 3 архитектур цикла агента в `approach`:
* **`"native"`** *(по умолчанию)* — **Native Tool Calling** (передача JSON-схем инструментов в API модели, наиболее точный и быстрый по числу шагов);
* **`"json"`** — **ручной JSON-цикл** (LLM возвращает JSON `{"action": "...", "input": "..."}`; работает даже с простыми/локальными моделями без поддержки native tools);
* **`"framework"`** — **LangGraph ReAct** (`create_react_agent` с автотрассировкой в MLflow).

**Пример JSON для Варианта А (составная задача на 2 инструмента):**
```json
{
  "question": "Узнай F1-score Чехова А и Достоевского Ф в отчётах и вычисли разницу между ними",
  "approach": "native",
  "mode": null,
  "max_iterations": 6,
  "temperature": 0.0
}
```
*(Попробуйте также передать художественный отрывок и попросить определить стиль, найти сюжеты в базе и посчитать соотношение метрик — агент сам вызовет `classify_style`, `search_plots`, `author_metrics` и `calc`.)*

**Поля запроса (`AgentRequest`):**
* **`question`** *(обязательно, `1..15000` символов)* — составной вопрос или инструкция для агента.
* **`approach`** *(`"native"` | `"json"` | `"framework"`, по умолчанию `"native"`)* — архитектура цикла рассуждений. При `mode != null` не используется.
* **`mode`** *(`null` по умолчанию)* — оставьте `null` для запуска цикла с инструментами.
* **`max_iterations`** *(`1..12`, по умолчанию `6`)* — максимум шагов «мысль → вызов инструмента → наблюдение», чтобы агент не зациклился.
* **`temperature`** *(`0.0..2.0`, по умолчанию `0.0`)* — при `0.0` агент максимально стабильно выбирает имена инструментов и аргументы.

**Что вернётся в `Response body` (`200 OK`):**
* `approach` — фактически отработавшая ветка (`"native"`, `"json"` или `"framework"`).
* `answer` — итоговый ответ агента пользователю.
* `iterations` — сколько шагов/итераций потребовалось агенту.
* `steps` — подробная трассировка каждого шага (массив объектов `AgentStepTrace`):
  * `step` — номер шага;
  * `tool` — какой инструмент вызван (`classify_style`, `search_plots`, `author_metrics`, `calc`, либо `final` / `error`);
  * `args` — аргументы, которые модель передала в инструмент (проверены Pydantic с `extra="forbid"`);
  * `result` — точный результат работы функции Python;
  * `raw` — сырой вывод модели (если применимо).

#### Вариант Б. Специализированные режимы UI (`Аналитик`, `Критик`, `RAG`)
Эти же режимы использует веб-интерфейс `ui.py` (`Streamlit`) под капотом:
1. **`"mode": "Аналитик"`** — сначала на Python сканирует весь датасет `data/plots_dataset.csv`, считает точное число записей, средний рейтинг, лучшие и худшие произведения по выбранной теме и передаёт расчёты в LLM (`approach` в ответе станет `"analyst"`):
   ```json
   {
     "question": "Проанализируй статистику и рейтинги произведений в жанре фантастика и фэнтези",
     "mode": "Аналитик",
     "temperature": 0.2
   }
   ```
2. **`"mode": "Критик"`** — подбирает до 4 произведений-кандидатов через `rag_search` и просит LLM сравнить их по атмосфере, конфликту сюжета, стилю и рейтингу (`approach` в ответе станет `"critic"`):
   ```json
   {
     "question": "Сравни сюжеты про конфликт человека и общества",
     "mode": "Критик",
     "temperature": 0.4
   }
   ```
3. **`"mode": "RAG"`** — запускает `rag_answer_async`, возвращает `approach: "rag"`, `iterations: 1`, а в `steps` кладёт найденные карточки сюжетов (`list[str]`).

## 4. Коды ответа и что делать при ошибках в Swagger UI

| Код в `Server response` | Где возникает | Причина | Как исправить |
|---|---|---|---|
| **`200 OK`** | Все эндпоинты | Запрос успешно обработан. | Результат находится в `Response body`. |
| **`400 Bad Request`** | `/classify`, `/ask`, `/agent` | `{"detail": "Пустой вопрос"}` — передана пустая строка `""`, одни пробелы или невидимые управляющие символы. | Введите осмысленный текст длиной минимум 1 видимый символ в поле `question`. |
| **`422 Unprocessable Entity`** | `/classify`, `/ask`, `/agent` | Ошибка валидации Pydantic: синтаксическая ошибка JSON, забыто обязательное поле `question`, `k` вне `1..10`, `max_iterations` вне `1..12`, `temperature` вне `0..2`, либо в `approach` указано значение не из списка `native`/`json`/`framework`. | Посмотрите поле `loc` и `msg` в теле ошибки `detail` и исправьте JSON по вкладке `Schema`. |
| **`502 Bad Gateway`** | `/ask`, `/agent` | Внешний LLM-провайдер отклонил ключ (`401`/`403`), сработал фильтр безопасности провайдера, провайдер недоступен или все fallback-модели вернули ошибку. *(Внимание: при `502` из-за блокировок/ключа проверьте баланс и актуальность `LLM_API_KEY` в `.env`, а также флаг `BYPASS_SYSTEM_PROXY=true`.)* | Проверьте валидность ключа и квоты в личном кабинете провайдера, затем перезапустите `uvicorn`. |
| **`503 Service Unavailable`** | `/classify`, `/ask`, `/agent` | Либо не загружен локальный классификатор, либо не задан `LLM_API_KEY` / учётные данные провайдера в `.env` (для `/ask` и `/agent`). | Для `/ask` и `/agent` заполните `LLM_API_KEY` в `.env` и перезапустите сервер. |
| **`504 Gateway Timeout`** | `/ask`, `/agent` | Облачная LLM или локальный инференс-сервер (`LLM_BASE_URL`) не ответили в пределах таймаута (`llm_timeout_seconds`). | Повторите запрос или смените модель/провайдера в `.env`. |
| **`TypeError: Failed to fetch`** | Любой | Браузер не может достучаться до `http://localhost:8000` (сервер `uvicorn` остановлен, упал или запущен на другом порту). | Проверьте окно терминала с `uvicorn`, при необходимости перезапустите сервер и обновите страницу `/docs`. |

## 5. Быстрый чек-лист проверки проекта через `/docs` за 2 минуты

1. **`GET /health`** → `Execute` → убедитесь, что `200` и `"model_loaded": true`.
2. **`POST /classify`** → `Try it out` → отправьте отрывок прозы → убедитесь, что локальная модель за миллисекунды определила автора без API-ключа.
